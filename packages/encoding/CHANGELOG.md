# @thomasfosterau/effect-encoding

## 0.1.0

### Minor Changes

- [#180](https://github.com/thomasfosterau/effect-web/pull/180) [`02bd69b`](https://github.com/thomasfosterau/effect-web/commit/02bd69b468f4a9e116dca82bf93e5c4f8beaad9a) Thanks [@thomasfosterau](https://github.com/thomasfosterau)! - The CJK encodings: `Encoding.encode` and `encodeStream` encode Shift_JIS, EUC-JP, ISO-2022-JP, gb18030, GBK, Big5 and EUC-KR, and `decode` / `decodeStream` decode them by the Encoding Standard's algorithms, once their indexes are provided with `Encoding.tablesLayer`. The indexes are opt-in entries (`@thomasfosterau/effect-encoding/japanese`, `/gb18030`, `/big5`, `/euc-kr`), so a bundle that never meets a CJK encoding never loads them. `isSupported` and `canEncode` take the tables as an optional second argument. Checked against the web-platform-tests ISO-2022-JP, gb18030, GBK and Big5 vectors.

- [#161](https://github.com/thomasfosterau/effect-web/pull/161) [`0d61df6`](https://github.com/thomasfosterau/effect-web/commit/0d61df62fd7a15d672a06c729aef9ba99a904281) Thanks [@thomasfosterau](https://github.com/thomasfosterau)! - New package `@thomasfosterau/effect-encoding`: the WHATWG Encoding Standard on Effect. `Encoding.getEncoding` resolves a label against the standard's 228 labels; `Encoding.sniffBom` is the BOM sniff as a standalone step; `Encoding.decode` and `Encoding.decodeStream` decode bytes and byte streams (multi-byte sequences split across chunks included), fatal by default with a typed `DecodeError { encoding, offset }` that gives the exact byte offset, and `"sniff"` / `"strip"` / `"keep"` BOM handling; `Encoding.isSupported` reports what the runtime can decode, with `ISO-8859-16` and `x-user-defined` bundled for runtimes (Node among them) whose `TextDecoder` lacks them, and `UnsupportedEncodingError` for any other missing encoding.

- [`35618cd`](https://github.com/thomasfosterau/effect-web/commit/35618cd72fe5dbd1336100ece1bd5fab81292cc1) Thanks [@claude](https://github.com/claude)! - Encode text: `Encoding.encode` and `Encoding.encodeStream` write UTF-8, every single-byte encoding and `x-user-defined`, failing on an unmappable character with a typed `EncodeError { encoding, offset, codePoint }`, or writing `&#N;` under `errorMode: "html"`. `canEncode` and `getOutputEncoding` (§4.3) go with them. Every single-byte encoding now decodes from the standard's bundled indexes rather than the runtime's `TextDecoder`, so it decodes the same on every runtime (Node's ICU disagrees with the standard on `IBM866`, `KOI8-U`, `windows-874`, `windows-1253` and `windows-1255`), and a runtime without the legacy encodings still decodes them. Checked against the web-platform-tests single-byte vectors.
