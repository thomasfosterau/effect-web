# @thomasfosterau/effect-web

## 0.2.0

### Minor Changes

- [#130](https://github.com/thomasfosterau/effect-web/pull/130) [`a28b97e`](https://github.com/thomasfosterau/effect-web/commit/a28b97efd10c938fed8610d9b6b6570c65c02c77) Thanks [@thomasfosterau](https://github.com/thomasfosterau)! - Add `Fullscreen` and `ScreenOrientation` to `./browser`, with `TestFullscreen` and `TestScreenOrientation` in `./testing`.

  `Fullscreen` shows an element fullscreen for a `Scope` (`enter`; closing the scope leaves fullscreen only if that element is still the fullscreen one), with the `withFullscreen` combinator, the fullscreen `element` and its `changes`. Failures are a `FullscreenError` (`Unsupported`, `NotAllowed`, `Failed`). `ScreenOrientation` reads `type` / `angle` / `current`, follows `changes`, and locks the orientation for a `Scope` (`lock`, `withLock`, which composes inside `withFullscreen`). Failures are an `OrientationError` (`Unsupported`, `NotAllowed`, `Aborted`, `Failed`). Both combined `layer`s include the new services.

- [#133](https://github.com/thomasfosterau/effect-web/pull/133) [`32e044f`](https://github.com/thomasfosterau/effect-web/commit/32e044f86ac5da943714d19d12828d5190cdd2b1) Thanks [@thomasfosterau](https://github.com/thomasfosterau)! - Add `IdleDetection` and `Battery` to `./browser`, with `TestIdleDetection` and `TestBattery` in `./testing`.

  `IdleDetection` wraps the Chromium-only `IdleDetector`: `requestPermission`, and `watch({ threshold })`, a stream of `{ user, screen }` whose detector is aborted when the stream ends; a threshold under one minute (`minimumThreshold`) fails `InvalidRequest`. Failures are an `IdleError` (`Unsupported`, `NotAllowed`, `InvalidRequest`, `Failed`). `Battery` wraps `navigator.getBattery()` as its own service: `status` (an `Option<BatteryState>`, with unknown times as `None`) and `changes`, both `None` / empty where the API is missing. Both combined `layer`s include the new services.

- [#129](https://github.com/thomasfosterau/effect-web/pull/129) [`18e1967`](https://github.com/thomasfosterau/effect-web/commit/18e1967b77231fe7b930b9e2839efb0cfa9730b6) Thanks [@thomasfosterau](https://github.com/thomasfosterau)! - Add `Notifications` to `./browser` and `TestNotifications` to `./testing`.

  `Notifications` wraps the page's `Notification` API: `permission` (`None` where unsupported), `requestPermission` (fails `NotAllowed` without transient user activation), `show(title, options)` — a notification held for a `Scope`, closed when it closes, whose `clicks` / `closes` streams replay from the moment it was shown and fail with the browser's `error` — and `permissionChanges`, over `PermissionStatus.changes("notifications")`. Failures are a `NotificationError` whose `reason` is `Unsupported`, `NotAllowed`, `Denied`, `InvalidData` or `Failed`. Both combined `layer`s include the new service.

- [#107](https://github.com/thomasfosterau/effect-web/pull/107) [`f0e215d`](https://github.com/thomasfosterau/effect-web/commit/f0e215de8884f7c0a1fb4701fe3ba6e8473ad1cb) Thanks [@thomasfosterau](https://github.com/thomasfosterau)! - Add the `./browser` and `./testing` entries.

  `./browser` wraps browser platform APIs as Effect services, each with a `make` over a structural slice of the platform object, a live `layer` that degrades where the API is missing, a tagged error and accessors: `Locks` (Web Locks — a lock held for a `Scope`, `withLock` / `withLockIfAvailable`, steal detection), `Navigator` (connectivity, languages, network information, user activation, Web Share, `sendBeacon`, vibration, storage persistence), `PageVisibility` (`whileVisible`), `MediaQuery` (preference streams), `WakeLock` (`keepAwake`, `keepAwakeWhileVisible`), `Broadcast` (schema-typed `BroadcastChannel`) and `PermissionStatus` (permission state as a stream over `@effect/platform-browser`'s `Permissions`), plus one `layer` with every live service.

  `./testing` provides an in-memory double for every `./browser` service and for `@effect/platform-browser`'s `Clipboard`, `Geolocation` and `Permissions` — each the real adapter over an in-memory platform object, with a `Control` service to drive it — a combined `layer`, and `observe` for race-free stream assertions.

  `@effect/platform-browser` (>= 4.0.0) is a new optional peer, needed only by these two entries.

- [#146](https://github.com/thomasfosterau/effect-web/pull/146) [`40d7c49`](https://github.com/thomasfosterau/effect-web/commit/40d7c49fda6f0ceab661fda246387396a4443722) Thanks [@thomasfosterau](https://github.com/thomasfosterau)! - Add `isCrossOriginRejectedWeb(request, expectedOrigin = new URL(request.url).origin)`, the SEC-CSRF-001 cross-origin predicate over a Fetch `Request`. `isCrossOriginRejected` is unchanged and still takes an `HttpServerRequest`; its doc comment now warns that a Fetch `Request` cast to it reads no `Origin` and passes every request.

- [#168](https://github.com/thomasfosterau/effect-web/pull/168) [`aba1812`](https://github.com/thomasfosterau/effect-web/commit/aba1812caec8e7cf3fd450f2d09c0c570d5c21ed) Thanks [@thomasfosterau](https://github.com/thomasfosterau)! - `./negotiate` compares media types as WHATWG MIME types through `@thomasfosterau/effect-mime`'s `MimeType` (now a dependency of `@thomasfosterau/effect-web`) instead of as lower-cased strings: an `Accept` instance and a write's `Content-Type` match `application/vnd.api+json` or `text/markdown` on their parsed essence, so case and HTTP whitespace never decide the verdict, and a `Content-Type` that is not a MIME type carries no media type and falls through as HTML.

- [#148](https://github.com/thomasfosterau/effect-web/pull/148) [`cd8ea52`](https://github.com/thomasfosterau/effect-web/commit/cd8ea52e03e628ae2ef6725015fc2432909510a1) Thanks [@thomasfosterau](https://github.com/thomasfosterau)! - Add a per-request metric scope to `./observability`. `withRequestMetrics(fn, onSettle)` runs `fn` with a fresh `Metric.Counter` and `MetricRegistry`, scoped through `AsyncLocalStorage`, and hands the settled `{ count }` to `onSettle` whether `fn` resolves or rejects. `incrementRequestMetric(amount?)` and `currentRequestMetrics()` add to the active scope and read it from plain code. `countingProxy(client, methodNames)` counts each call of a named method on a client, invoking it with the real client as `this`: a per-request query count. The entry now imports `node:async_hooks`; on Workers that needs `nodejs_compat`.

- [#105](https://github.com/thomasfosterau/effect-web/pull/105) [`789086c`](https://github.com/thomasfosterau/effect-web/commit/789086c8b8544bbb1cd55154003c6df18474bd02) Thanks [@thomasfosterau](https://github.com/thomasfosterau)! - Add the `./service-worker` entry: Cache Storage as typed effects (`openCache`, `deleteCachesExcept`, `CacheError`), the five caching strategies (`cacheFirst`, `networkFirst` with an optional timeout, `staleWhileRevalidate`, `cacheOnly`, `networkOnly`) with the `isCacheable` write-back filter, `precache`, and listeners for `fetch` (a synchronous route table), `install` / `activate` and `message` (Schema-decoded) whose work runs inside `respondWith` / `waitUntil`. `caches` and `fetch` are context references with global defaults (`Caches`, `FetchHttpClient.Fetch`); `memoryCacheStorage` is an in-memory `CacheStorage` for tests.

- [#142](https://github.com/thomasfosterau/effect-web/pull/142) [`9cc5a27`](https://github.com/thomasfosterau/effect-web/commit/9cc5a27e1cb2132f10fbbdd914a999df25d4d407) Thanks [@thomasfosterau](https://github.com/thomasfosterau)! - Add persistent notifications to `./service-worker`: the `Registration` context reference (defaulting to the worker's `self.registration`), `showNotification` and `getNotifications` failing with `ShowNotificationError`, and the `notificationClickListener` / `notificationCloseListener` builders, which decode `notification.data` through a schema and run the handler inside `waitUntil`.

- [#149](https://github.com/thomasfosterau/effect-web/pull/149) [`d224d12`](https://github.com/thomasfosterau/effect-web/commit/d224d1241b806e224b0d53b30b23c0eccfb5860d) Thanks [@thomasfosterau](https://github.com/thomasfosterau)! - Add `siteBase({ key, fallback }): Effect<string>`, the canonical site base read from configuration rather than the request origin. It reads `key` through the ambient `ConfigProvider`, normalises the value to an `http(s)` origin with no trailing slash, and never fails: a missing key, a provider error or an invalid value (the last after a `site-base.invalid` warning) yields the application's `fallback`. `normalizeSiteBase(value): Option<string>` exposes the check on its own.
